## Data Modeling

Data Modeling aik process hey jis mey ham data ko is traha organize or structure kartey k woh efficiently (in less time and less resources) store, manage or read kia ja sake yeah hoti hey data ki modeling.

ismey ham dehktay k konsa data store karna hey jo hamaray use case kelye important hey, phir ham tables/collections ka schema usi hisa say define kartey heyn.

Phir ham data ko normalize kartey heyn koee redundancy na ho, mongo db mey is kaam ko relationship k hisab say nested yar referencing k zariye solve kia jata hey.

## Relation

Aik relation batata hey k different type ki entities/object ya documents apas mey kesay relate kar rahey heyn for example a product have many reviews.

To product or reviews ka apaps mey one to many relationship hey.

## On-to-One Relation

Jab aik collection mey majood aik document kisi dosri collection k aik or sirf aik documents say relate karta hey to isay one to one relation ship kehtay heyn.

For example aik ecommerce system har user ki sirf aik hi user profile ho sakti hey.

```mongodb
{
  "_id": ObjectId("60c72b2f9c4f8d22f8b03d3c"),
  "username": "ali_khan",
  "email": "ali.khan@example.com",
  "profile": {
    "full_name": "Ali Hassan Khan",
    "phone_number": "+923001234567",
    "address_line1": "House 123, Street 5",
    "city": "Karachi",
    "country": "Pakistan",
    "marketing_consent": true
  }
}
```

## One to Many Relation

Jab aik collection mey majood aik document kisi dosri collection k 2 ya 2 say ziyada documents k sath relate karta hey to isay one to many relation kehtay heyn.

Abh ismey konsa method use karna chaye Nested Doc ya Rerferencing for mantaining one to many relation ship is totally depne on the given criteria for the Nested Document.

There three type of many relationship

1. One to few 

2. One to many

3. One too many

### One to Few

For example aik customer k koee chan aik hi card ho saktey heyn jinko woh hamari website per checkout kelye save kar sakta hey.

In that case let say we allowed him 5 cards to is scenario mey nesting use karni chayee, why becuase na to data redundancy hey, na data size mey itna ziyda hey or data closeness to the user is high.

```mongodb
{
    username: "kashif12"
    age: 23
    cards: [
     {number: "1234 3421 2365 9754", expiry_date:"07/26", CVV: "123"},
     {number: "9876 2345 9876 2945", expiry_date:"02/27", CVV: "234"}
  ]
}
```



### One to Many

It's type of one to many relation where you have limit like you've allowed 20 addresses for shipping to add on your website not more then that in that case you can also use nested documents to store shipping addresses.

## One to Too Many

It's one to many relationship where the limit of related document is not confirmed and can infinite grow, for example product reviews.

In that scenario we have to use refrencing to store reviews in different table.

## Many to Many

Jab aik collection mey majood ai documents dosri collections k multiple documents say related karey and vice versa.

In many to many relation we alwasy go with refrencing approach. 

## Type of Referencing

### Child Referencing

Jab parent document apney child ka refrence store karta hey isay child refrencing kehtay heyn for example if product store an array of reviews ids that mean the product collection is parent that refring to it's child, that's called child refrencing.

```mongodb
{
    _id: "1"
    title: "iPhone",
    price: "$500"
    review: [123, 343, 564] // child refrencing
}
```

### Parent Refrencing

Jab child document refer kart hey apney parent ko this is called parent refering but as I've gave you an example of product collections storing reviews ids but at some point there are so many ids that make no sense and clutter the product document.

It's best for one to many relationship

```mongodb
{
    _id: "1"
    title: "iPhone",
    price: "$500"
    review: [123, 343, 564]
}
```

But ham abhi is problem ko solve karney kelye refrencing ko ulta kar deytay heyn abh parent kuxh bhi store nahi karey ga balkey child yani review jis product ka woh hey us product ko refer kare ga

When child refrencing it's parent that's called parent referencing 

```mongodb
{
    _id: "3421",
    review: "nice!",
    parent: "1" // parent refrencing
}
```

## Two way refrencing

Jab child parent ko parent child ko refer karta hey to yeah two way refrencing kehtay heyn.
