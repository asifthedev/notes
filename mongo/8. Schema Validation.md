# Schema Validation

JSON Schema validation say ham documents k aik consistent structure ko enforece kar saktey heyn, or data kis type ka hoga or kia kia hoga is cheez ko enforece kar saktey heyn.

Schema ko do traha say enforece kia ja sakta hey

1. While Creating a New Collection

2. On An Existing Collection

## Schema Validation for New Collection

Jab ham aik new collections banatey heyn to Option Object k ander validator name k object k ander ham apna schema ko pass kar saktey heyn.

```mongodb
db.createCollection("users", {
    validator: {
        $jsonSchema: {...}
    }
})
```

### $jsonSchema

It's an object under the validator option/object, where we actually define our schema.

```mongodb
$jsonSchema: {
    "bsonType": "object"
}
```

Yani yeah jo schema hey yeah itself bhi aik object k formate mey hey ya phir yeah object/documents kelye hey.

```mongodb
$jsonSchema: {
    "required": ["name"]
}
```

Yaha pay ham batatey heyn is collection mey konsay fields required heyn in that case name is must to pass.

```mongodb
$jsonSchema: {
    "additionalProperties": false
}
```

Yani ji fileds ko ham ney schema k `properties` object mey define kreygayn, kia us k illawa koee or fileds ham insert kar saktey heyn, `false` mean nahi or `true` means yes.

```mongodb
$jsonSchema: {
    properties: {
        name: {
            bsonType: "string",
            description: "Name must be type of string"
        }
    }   
}
```

The `properties` object is used to actually define the constraints for the fields of the documents. 

## Data Types and Their Options

### string validation

```monkey
{
  bsonType: "string",
  description: "must be a string",
  minLength: 5,           // minimum character count
  maxLength: 100,         // maximum character count
  pattern: "^[A-Za-z]+$", // regex pattern
  enum: ["option1", "option2"] // allowed values only
}
```

### Number (int, long, double, decimal) Validation

```mongodb
{
  bsonType: "int",        // or "long", "double", "decimal"
  description: "must be an integer",
  minimum: 0,             // minimum value (inclusive)
  maximum: 100,           // maximum value (inclusive)
  exclusiveMinimum: 0,    // minimum value (exclusive)
  exclusiveMaximum: 100,  // maximum value (exclusive)
  multipleOf: 5,          // must be divisible by this
  enum: [10, 20, 30]      // allowed values only
}
```

**BSON number types:**

- `int` - 32-bit integer
- `long` - 64-bit integer
- `double` - 64-bit floating point
- `decimal` - 128-bit decimal (high precision)
- `number` - any numeric type

### Boolean Validaton

```mongodb
{
  bsonType: "bool",
  description: "must be a boolean"
}
```

### Object (Embedded Documents) Validation

```mongodb
{
  bsonType: "object",
  required: ["field1", "field2"],
  properties: {
    field1: { bsonType: "string" },
    field2: { bsonType: "int" }
  },
  additionalProperties: false,  // disallow extra fields
  minProperties: 1,             // minimum number of properties
  maxProperties: 10,            // maximum number of properties
  dependencies: {               // conditional requirements
    field1: ["field2"]          // if field1 exists, field2 required
  }
}
```

### Array Validation

```mongodb
{
  bsonType: "array",
  description: "must be an array",
  items: {                      // schema for array items
    bsonType: "string"
  },
  minItems: 1,                  // minimum array length
  maxItems: 10,                 // maximum array length
  uniqueItems: true,            // all items must be unique
  additionalItems: false        // disallow items not matching schema
}
```

**Array with multiple types:**

```javascript
{
  bsonType: "array",
  items: [
    { bsonType: "string" },     // first item must be string
    { bsonType: "int" }         // second item must be int
  ]
}
```

### Date

## Advanced Features

### Multiple Types (oneOf, anyOf, allOf)

```javascript
{
  // Field can be string OR number
  anyOf: [
    { bsonType: "string" },
    { bsonType: "int" }
  ]
}

{
  // Field must match exactly one schema
  oneOf: [
    { bsonType: "string", minLength: 5 },
    { bsonType: "int", minimum: 100 }
  ]
}

{
  // Field must match all schemas
  allOf: [
    { bsonType: "string" },
    { minLength: 5 },
    { maxLength: 50 }
  ]
}
```

### Not (Negation)

```javascript
{
  not: {
    bsonType: "string"  // anything BUT a string
  }
}
```

## Validation Level & Action

### Strict + Error (Most Common)

```javascript
db.createCollection("products", {
  validator: { $jsonSchema: { 
    bsonType: "object",
    required: ["name", "price"]
  }},
  validationLevel: "strict",
  validationAction: "error"
})
```

**Explanation:** Validates ALL documents (new and existing) on insert/update. If validation fails, the operation is **rejected** and returns an error.

### Moderate + Error

```javascript
db.runCommand({
  collMod: "products",
  validationLevel: "moderate",
  validationAction: "error"
})
```

**Explanation:** Only validates documents that **already match** the schema. Invalid existing documents can stay invalid, but once fixed, must remain valid. Operation is **rejected** on failure.

### Strict + Warn

```javascript
db.runCommand({
  collMod: "products",
  validationLevel: "strict",
  validationAction: "warn"
})
```

**Explanation:** Validates ALL documents, but if validation fails, it only **logs a warning** in MongoDB logs and **allows** the operation to succeed anyway.

### Moderate + Warn (Most Lenient)

```javascript
db.runCommand({
  collMod: "products",
  validationLevel: "moderate",
  validationAction: "warn"
})
```

**Explanation:** Only checks documents that already match the schema, and even then just **logs warnings** without blocking operations. Good for gradual migration.
